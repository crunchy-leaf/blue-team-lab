# Executive Summary
During routine network monitoring, suspicious TCP connection activity was identified targeting a Windows 11 workstation. Packet capture analysis revealed a high volume of connection attempts originating from an internal Kali Linux system and directed toward numerous TCP ports on the target host within a short time period. The observed behavior was consistent with network reconnaissance activity.

An investigation was conducted using Wireshark packet captures, Sysmon endpoint telemetry, and Splunk log analysis. Network traffic analysis confirmed the activity was generated by an Nmap TCP Connect scan (-sT) designed to identify accessible services on the target system. While the scan activity was clearly visible within packet capture data, corresponding Sysmon Event ID 3 logs were not present on the target host because the telemetry source primarily records network connections initiated by the local system. As a result, the investigation relied primarily on network evidence to reconstruct the sequence of events.

Analysis determined that the activity was limited to reconnaissance and service discovery, with no evidence of exploitation, malware execution, privilege escalation, persistence, or lateral movement. The investigation also identified a visibility gap in the monitoring architecture, demonstrating the importance of combining endpoint telemetry with network-based monitoring solutions to improve detection coverage of inbound reconnaissance activity.
